# G2 — восстановление управления после потери фокуса, 2026-11-03

## Основание и выбор задачи

Автор поручил следующую небольшую игровую правку без новых творческих решений,
ассетов и APK, в отдельной ветке с проверками и обычным push, без PR и merge.
Выбран подтверждённый дефект существующей ходьбы и взаимодействия на крыше:
потерянное событие отпускания пальца оставляло TouchScreenButton захваченным.
Герой мог продолжать идти, либо новое касание не начинало движение даже после
сброса Input системой. Это исправление управления G2/G3 (CODEX_TASKS.md),
поддерживающее свободное поведение игрока из GDD §7, а не новая сюжетная механика.

Альтернативы: музыка G6c требует исходника и согласованного использования;
канонические исходы — утверждённых условий, текстов и постановки; сохранение
полученных исходов G7 нельзя подменять сохранением технического выхода G5.
Поэтому для этой итерации выбрана практическая правка уже играбельного цикла.

База: `000eb482a1d13c2ba7786a9c72eb89bf2b95c474`.
Ветка: `codex/rooftop-focus-input`, поверх неслитой цепочки G6a/G6b и мышиного
исправления диалога. Основная ветка не меняется.

## Изменение и приёмка

- `scripts/rooftop.gd`: обе нотификации потери фокуса вызывают отложенный сброс
  владения пальцами у видимых TouchScreenButton и существующий
  `SceneSwitch.release_pressed_input()`. Тот же подход уже работает в хабе.
- `tests/g2_focus_smoke.gd`: сценарии приложения и окна, два удерживаемых пальца,
  потерянные отпускания, заранее сброшенные системой действия, новые ID пальцев,
  отпускание новых касаний, клавиатура и повторные нотификации.

Герой тормозит по прежним правилам движения. Новое касание снова работает.
Скрытые варианты остаются скрытыми; потеря фокуса сама не выбирает реплику и не
меняет состояние/страницу диалога. Глобальная пауза, новые настройки, сцены,
тексты, графика, анимации и музыка не добавлены. Правило Pixelorama сохраняется.

## Ограничения

Фокус моделируется нотификациями приложения/окна; ввод проходит через
Input.parse_input_event. Это воспроизведение потерянных отпусканий, а не проверка
реальной ОС телефона. Физические Android/Windows устройства не проверялись,
экспорты и APK не запускались. Новое визуальное ревью не требуется для правки,
не меняющей отрисовку. PR не создаётся, merge не выполняется.

## Дополнение: сенсорный выбор после восстановления фокуса

По замечанию статического ревью в отдельной ветке
`codex/rooftop-focus-touch-check` от `fab7c694978c57ce8deb30069e70dcd8f19a9eaf`
расширен только существующий `tests/g2_focus_smoke.gd` (и этот отчёт).
Игровые скрипты, сцены и настройки не изменены.

После обеих разновидностей потери/возврата фокуса новый палец выбирает ответ:
сначала без эмуляции мыши, чтобы она не скрывала возможный отказ touch-кнопки,
затем с эмуляцией. Проверяются ровно один сигнал правильного выбора, скрытие
вариантов, снятие действия кнопки и отсутствие повторного выбора/изменения
состояния при позднем отпускании. Исходная настройка эмуляции восстанавливается.
Добавлено 12 утверждений: адресный набор **36 PASS, 0 FAIL, exit 0**.

Все восемь наборов выполнены на Godot 4.7.2 одним проходом, разделённым на две
команды: `focused` (импорт, G2 focus/G2 rooftop/G3 dialogue/G3 mouse) и `remaining`
(G4/G5/G6a/G6b, старт). Сумма **350 PASS, 0 FAIL**, каждый exit 0; импорт и старт
также exit 0, без ERROR/Parse Error. Команды движка те же, что выше.
`git diff --check` прошёл. Свидетельства сохранены в
`/workspace/scratch/invariant-rooftop-focus-touch/evidence.zip`.

Реальное сворачивание Android-приложения, потеря фокуса на телефоне и порядок
событий конкретного устройства **остаются непроверенными**. Синтетические
нотификации и Input.parse_input_event не заменяют такую проверку. APK не собирался.

Следующая выбранная игровая задача (ещё не выполнена): осмотр существующих
точек хаба мышью. GDD §17 разрешает осмотр окружения при неподвижном герое.
В `street_hub.gd::_unhandled_input` левая кнопка проверяет только сумку и сразу
возвращается; точки Street/House/Entrance — TouchScreenButton с уже существующим
`_on_point_tapped`, который выбирает и осматривает объект. Перед правкой следует
воспроизвести отсутствие реакции на щелчок, затем направить его в этот же метод.
Приёмка: три существующие точки выбираются/осматриваются мышью; герой не ходит;
сумка сохраняет приоритет; открытый плеер и переход на крышу блокируют осмотр;
масштабирование, касания и клавиатура работают без повторного действия.
Тексты остаются существующими PLACEHOLDER_NON_CANON. Новые ассеты, творческие
решения, музыка и APK не требуются; задача зависит от неслитой базы G6a/G6b.
