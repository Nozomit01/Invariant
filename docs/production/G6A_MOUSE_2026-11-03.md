# G6a — осмотр существующих точек хаба мышью, 2026-11-03

## Задача и основание

Автор разрешил минимальную реализацию осмотра существующих точек хаба мышью,
с сохранением текстов, графики и неподвижности героя, тестами мыши/касания/
блокировки плеером, отдельной веткой и обычным push без перезаписи, PR и merge.
APK отложен. GDD §17 закрепляет осмотр окружения без ходьбы в обычном хабе;
CODEX_TASKS.md G6 требует осмотр и использование плеера в едином игровом цикле.

База: `e978ca6beb1287bd79c7b79a5b2d203c17a90ceb`.
Ветка: `codex/hub-mouse-inspection`. Она продолжает неслитую цепочку G6a/G6b
и исправлений ввода; это не изолированный патч поверх main.

## Поведение и изменение

До правки левая кнопка мыши проверяла только сумку, затем обработчик выходил.
Street/House/Entrance работали как TouchScreenButton и с клавиатурой. Новый
тест воспроизвёл отсутствие осмотра мышью для всех трёх точек.

`street_hub.gd`: после проверки сумки щелчок проверяет существующие видимые
прямоугольные области точек и вызывает прежний `_on_point_tapped(index)`.
Сумка имеет приоритет. Координаты переводятся обратным canvas transform.
Эмулированная касанием мышь (`device == -1`) пропускается, поскольку касание
уже обрабатывает TouchScreenButton. Это исключает повторный осмотр.

Ограничение `_can_use_hub()` сохранено: открывание, открытый плеер, закрывание
и переход на крышу блокируют осмотр. Тексты, сцены, графика, музыка, модели
состояния и настройки проекта не менялись. Герой остаётся на месте и курит.
Существующие технические описания остаются `PLACEHOLDER_NON_CANON`.

её скрипта, который только считает вызовы `_inspect()` и передаёт выполнение
родителю: счётчик обнаруживает повторный осмотр, даже если итоговая надпись
та же. Ввод проходит через `Input.parse_input_event` и `flush_buffered_events`.

## Ограничения

Это синтетический ввод и headless-проверки, а не физическая мышь/сенсорный
экран и не проверка Windows или Android-устройства. Порядок событий реальной
ОС, APK и экспорт Windows в этой задаче не проверялись. Графика/анимации не
создавались; требование Pixelorama сохраняется. PR не создаётся, main и
существующие ветки не меняются. После этой небольшой итерации работа остановлена.
