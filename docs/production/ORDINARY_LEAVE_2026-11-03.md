# Обычный «Уход»: техническая последовательность — 2026-11-03

## Поручение и границы

Прямое поручение: минимальный технический срез GDD §19.2 от действия у выхода
до существующего хаба, однократная фиксация события в памяти текущей сессии,
проверки и независимое ревью. База `f9de3afc925e5480c67d6fced1a467da9579b9f2`,
ветка `codex/ordinary-leave-sequence`. Без сохранений, новых рисунков, финального
монолога, «Прыжка», PR, merge и APK. Существующие GDD/Bible не меняются.

Это **не завершённая художественная концовка**. Реального аудио, постановки
выхода из дома и анимации поворота нет. Используются существующие геометрия,
маркеры и текстовые пометки PLACEHOLDER_NON_CANON. Будущие рисунки и анимации
создаются отдельно только в Pixelorama.

## Последовательность

1. E / «Уйти» у существующего выхода закрывает разговор и один раз начинает
   уход. Разговоры и их завершённость не являются условием выхода.
2. Загружается существующая улица. Управление хабом пока отключено.
   LEAVING: текстовая заглушка «Выход из дома», 0,25 с.
3. WAITING: показ существующего героя, неподвижный кадр, 0,35 с.
4. IMPACT_CUE: место звука обозначено «Место звука удара (аудио нет)», 0,20 с.
   Звуковой файл не проигрывается и не выдается за готовый.
5. TURNING: направление существующего маркера Look меняется с -1 на +1,
   к дому; 0,25 с. Это обозначение поворота, не новая анимация персонажа.
6. TRANSITION: герой/улица скрываются, существующий тёмный фон и пометка
   «Переход после ухода», 0,25 с. Плавное художественное затемнение не добавлено.
7. Только по завершении перехода фиксируется событие; включается прежний
   неподвижный хаб, осмотр, плеер и запуск нового прохода.

Тело и девушка в этой последовательности не показываются. Мрачный вариант
с плачем после монолога не реализован. Тайминги служат проверке порядка, не
являются финальным ритмом постановки. При потере фокуса отсчёт стадии
останавливается; после возврата продолжает тот же этап. Нажатый ввод очищается.

## Фиксация в памяти

`scripts/state/session_outcomes.gd` — маленький RefCounted со статическими
полями, без class_name, autoload, файлов, UI прогресса и разблокировок.
Два существующих скрипта сцены используют его через preload.

Каждому отдельному уходу присваивается departure_id. Повторный begin возвращает
тот же активный ID; получить его может одна сцена. После завершения записывается:
`{departure_id, outcome: ordinary_leave, technical_presentation: true}`.
Повторный complete того же ID ничего не добавляет. Следующий настоящий проход
может породить отдельное событие: однократность относится к каждому уходу,
а не к запрету повторного прохождения. Наклейки и счётчик разных концовок
из этих событий пока не вычисляются.

При удалении незавершённой сцены событие отменяется. Ошибка загрузки хаба
отменяет pending ID и возвращает возможность действия на крыше. Прямой запуск
хаба без ухода не записывает исход. `events()` отдаёт глубокую копию; новый
процесс начинает с пустой историей. Дисковая сериализация отсутствует.

## Изменения

- `rooftop.gd`: начало ухода с ID и отмена при ошибке смены сцены.
- `technical_scene_switch.gd`: возвращает фактический Error вызова смены сцены;
  хранит раздельный фокус приложения и окна. Маленький получатель уведомлений
  под корневым Window переживает удаление крыши и появление хаба. Без autoload.
  Узел внутренний (`INTERNAL_MODE_BACK`), не считается второй игровой сценой.
  Первоначальный фокус окна читается у DisplayServer вне headless.
- `street_hub.gd`: компактная последовательность перед активацией хаба,
  остановка таймера при потере фокуса, отмена незавершённого ID при выходе.
- `session_outcomes.gd`: описанный журнал только в памяти процесса.
- `ordinary_leave_smoke.gd`: проверки нового поведения; прежние тесты циклов
  ожидают окончание более длинного перехода (100 кадров вместо 30), без удаления
  прежних утверждений. Прямой тестовый запуск хаба сохраняет прежний путь 0,35 с.
- `ordinary_leave_focus_smoke.gd`: потеря и восстановление фокуса в промежутке
  сцен; фокус приложения не подменяет отсутствующий фокус окна.

получатель уведомлений первоначально был обычным дочерним узлом. Он переведён
во внутренний узел; сами проверки числа сцен не ослаблены. Ревьюер повторно
подтвердил получение уведомления восстановления этим внутренним узлом.
