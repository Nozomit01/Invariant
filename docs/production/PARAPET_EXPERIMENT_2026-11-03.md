`0b177bd4949019a6476c181c95683b7a5d5d0c4d`.
Это исходная точка сравнения, **не интеграция готовых тайлов**.
Сцена, скрипты игры, графика, коллизии/ограничения движения и канон не менялись.

## Получение исходников

Поручение указало три вручную нарисованных в Pixelorama варианта:

- `parapet_variants_abc.png` — `libfile_f70b6188532881918ac0fdf7a6804fbd`,
  file ID `file_0000000061e081f58fa9616a3dba35c2`, версия 0, 481 байт.
- `parapet_variants_abc.pxo` — `libfile_22da696f348c81919de1f390a7a80f1e`,
  file ID `file_00000000670081fdb7312cdc955ec7e8`, версия 0, 3056 байт.

Library успешно подготовила обе передачи, но официальный transfer helper
при единственном вызове для каждого файла завершился exit 1:
`library file transfer failed: download failed`.
В целевых путях файлы отсутствуют. Точный HTTP-код и причина не возвращены;
явный отказ автоматического approval review не наблюдался. Сетевая политика
среды restricted/enforced; утверждать конкретный вид сетевого отказа нельзя.
Ни повторной загрузки, ни обхода ограничения не выполнялось.

Чтение PNG через Library вернуло метаданные 96×16 и указатель на изображение,
но не доступные пиксели. Автоматическое текстовое описание явно не соответствует
поручению и не использовано как визуальное доказательство. Цвета, края, швы и
содержимое вариантов пока **не оценены**. Исходник PXO также не открывался.

## Подготовленная точка сравнения

Godot `4.7.2.stable.official.ed1daf0bf`, X11 :89, Compatibility / Mesa llvmpipe,
Dummy audio. Окно 960×720, логический кадр 320×240. Запуск exit 0;
три save_png завершились OK. Драйвер предупреждает о недоступном V-Sync.

- [Начальная позиция](parapet-experiment/01-entry.png).
- [Открытый диалог](parapet-experiment/02-dialogue.png).
- [Позиция у выхода без ухода со сцены](parapet-experiment/03-exit.png).

Снимки просмотрены. В диалоге существующая панель закрывает часть нижней сцены
и персонажа; это свойство исходного прототипа, не результат новых тайлов.
Проверка будущего парапета нужна и с открытым, и с закрытым диалогом.
Скрипт съёмки сохранён рядом. Первый черновой скрипт ожидал только process-кадры
и неверно относил кадр перехода к крыше; исправлено ожидание physics-кадров и
добавлены assert текущей сцены/видимого диалога. В отчёте только проверенные кадры.

## Геометрия и следующий разрешённый шаг

- Предварительное разрешение проекта 320×240; GDD §24 требует крупные читаемые
  пиксели и приглушённую палитру, без обязательного нового фильтра.
- Roof — полоса x=12…308, y=168…184. Боковые маркеры x=12…16 и x=304…308.
- Герой: y=154, прямоугольник высотой 28, ноги на y=168.
- Движение ограничивает clamp x=22…298 в rooftop.gd; отдельную новую физику
  парапета создавать не требуется и это не разрешено данным экспериментом.
- Если экспорт действительно содержит три горизонтальных тайла 32×16, девять
  тайлов займут внутреннюю ширину 288 пикселей (x=16…304). Это гипотеза по
  метаданным, которую нужно проверить по изображению и PXO перед раскладкой.

После разрешённой передачи байтов: проверить PNG/PXO, сохранить исходники без
перерисовки, использовать исходный размер пикселей и nearest filtering. Примерять
отдельный декоративный слой за персонажем; исходную полосу пола, границы, ввод
и позиции интерактивных точек оставить неизменными. Порядок A/B/C выбирать после
осмотра отличий: спокойные участки между редкими акцентами, без циклического ABC.
Снять те же три состояния, проверить швы, контраст и читаемость, затем решить,
улучшает ли раскладка композицию. Изменять сам арт можно только в Pixelorama.

Нужна разрешённая передача PNG и PXO в эту облачную среду. До неё невозможно
обоснованно выполнить раскладку и оценить её качество. PR, merge, APK и платные
сервисы не запускались. Полный игровой suite повторно не запускался: runtime
не изменён, выполнен только описанный визуальный старт исходной сцены.
