# INVARIANT — технический базис (D1, обновлено под Android + Windows)

**19 октября 2026. Статус: на утверждении автора. Это документ, не реализация.** `project.godot`, сцены и CI до разрешения не создавать.

## Платформы — подтверждено автором

- **Android и Windows одновременно с начала разработки**, один проект Godot 4.x, общая игровая логика/сцены и отдельные адаптеры ввода/UI там, где необходимо.
- **Android — обязательная платформа для регулярного ручного тестирования**: у автора только смартфон, ПК нет. Не откладывать APK до финальных стадий.
- **Windows x86_64 — параллельный экспорт под Steam**. Тот же набор сцен и механизмов; реальное тестирование на Windows перед публикацией потребует отдельного ПК/тестировщика.
- Проверяемые после каждого игрового среза файлы: **отладочный .apk**, **Windows .zip (с .exe и необходимыми файлами)**; обе сборки — артефакты GitHub Actions. Хостинг артефактов имеет сроки хранения, поэтому важные билды сохранять отдельно по согласованию.
- Сборка на GitHub Actions после авторского разрешения и настройки экспорта: **Godot 4.7.2 stable + соответствующие export templates + Android SDK/JDK** для Android, preset Windows Desktop для Windows. Из одного коммита собирать оба артефакта; если что-то не собрано, отчёт содержит лог, а не фиктивную ссылку.
- Android debug APK подписывается стабильным debug-ключом, который **не хранится открыто** в публичном репозитории. Для последовательной установки/обновлений нужен неизменный package ID + подписывающий сертификат; способ хранения ключа утвердить при настройке CI. Релизные ключи/Steam-секреты не добавлять в исходники.
- Перед публикацией в Steam нужен ручной запуск Windows-версии на реальном ПК; облачная сборка `.exe` — не доказательство исправной игры.

## Технические предложения для одного проекта (ещё не утверждены)

| Параметр | Значение | Почему |
|---|---|---|
| Godot | **4.7.2 stable, Standard, GDScript** | Официальная стабильная версия на 19.10.2026, один номер для шаблонов/CI. |
| Основа | **чистый 2D** (CanvasItem); никаких 3D/Mono/Jolt | Соответствие GDD; минимум зависимостей. |
| Логический формат | **4:3**, предложение: **320×240** | Визуальная стилистика. Проверить читаемость диалогов и плеера на телефоне до утверждения размера. |
| Масштаб | `viewport`, `aspect=keep`, integer scaling | Резкие пиксели, без искажений; на вытянутом экране смартфона будут поля. Нужно предусмотреть UI и зоны касаний, не скрывающие сцену. |
| Фильтрация | `nearest` для пиксельных текстур | Не размывать спрайты. Шрифты оценить отдельно. |
| Рендер | `Compatibility` (OpenGL/OpenGL ES) как стартовое предложение | Более широкий охват GPU, включая Mali; подтвердить запуск на устройстве. |
| Android | **arm64-v8a**, landscape, touch controls, безопасные зоны | Устройство автора и современные Android-устройства. UI не копирует клавиши ПК. |
| Windows | WASD/стрелки, E/взаимодействие, мышь для выбора; Esc — плеер по GDD | Настраиваемое сопоставление InputMap; назначение клавиш — рабочее предложение. |
| Диалоги | Единая логика; экранные варианты выбора и молчания для тача и ПК | Во время большинства диалогов герой может двигаться и уйти. |
| Хаб | Полный GDD §17–18, без свободного перемещения | Подтверждённое авторское решение. |
| Демофинал | Два разных исхода → отдельный экран завершения демо → полный хаб → повторы | Не делать end screen после двух повторов одной и той же ветки. |

## Порядок работ после отдельного разрешения Gate 0

1. **G1a:** минимальный открываемый проект Godot и простая заглушка запуска без художественного контента.
2. **G1b:** экспортные пресеты **Android debug APK + Windows** и минимальный CI, автоматически создающий **две сборки**. Убедиться, что оба артефакта реально существуют и доступны для скачивания с телефона. Одна узкая задача, отчёт с командами и логами. Если настройка Android signing/SDK требует отдельного шага, остановиться и сообщить причину.
3. **G1c:** установить APK на телефон автора, проверить запуск, ориентацию landscape, чёрные полосы/масштаб, тач и читаемость текста; сохранить воспроизводимый тестовый отчёт. В случае проблем вернуть к исправлениям до создания большой игровой логики.
4. Далее — крыша, диалоги, скрытые состояния, исходы, полный хаб, сохранения и экран демофинала согласно `docs/production/CODEX_TASKS.md`. **Каждое завершённое изменение доступно для мобильного теста по возможности**, без наращивания дорогостоящих параллельных агентов.

## Что ещё требует согласования

- Число пикселей (предложение 320×240), способ масштабирования и расположение сенсорных контролов.
- Package ID Android и решение по debug signing.
- Конкретные InputMap-клавиши, UI и способ тестирования на реальном Windows-ПК.
- Отдельный запуск реализации: пока Gate 0 не пройден; нужен явный допуск автора.
