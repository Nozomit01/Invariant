# INVARIANT — технический базис для утверждения (D1)

**Дата:** 2026-10-19. **Статус:** предложение, НЕ разрешение создавать игровой код. Никаких технических настроек в `project.godot` пока нет.

## Предлагаемые параметры

| Решение | Предложение | Причина / проверка |
|---|---|---|
| Движок | **Godot 4.7.2 stable**, Standard, **GDScript** | На 19.10.2026 это актуальная стабильная ветка 4.7.x; Godot 4.8 только beta. Один зафиксированный номер для локальных проверок и CI. |
| Графика | **2D**, без 3D-физики, без Jolt/Mono | Новый проект с нуля, не перенос старой базы. |
| Цель | **Windows x86_64** (Steam) | Android — только позднее отдельным этапом. |
| Логическое разрешение | **320 × 240**, 4:3 | Совместимо с художественным ориентиром GDD и крупным пикселем. Это **предлагаемый размер**, проверить читаемость диалогов, плеера и титров перед окончательным утверждением. |
| Окно разработки | **960 × 720** (3×), ресайз разрешён | Для ручных проверок пиксельного масштаба; если на маленьком дисплее не помещается, менять размер окна без изменения логического разрешения. |
| Stretch | `viewport`; `aspect=keep`; `scale_mode=integer` | Сохранение 4:3 и целых пикселей с полосами по бокам/сверху; не растягивать картинку под 16:9. |
| Фильтрация | `nearest` для 2D-текстур | Исключить размытые пиксели; UI и пиксель-шрифты требуют отдельного визуального теста. |
| Рендер | **Compatibility / gl_compatibility** на первом шаге | Предпочтение совместимости Windows 2D; позже можно проверять другой рендер на реальном железе. |
| Управление ПК | WASD / стрелки — движение; **E** — взаимодействие; **мышь/клавиатура** — выбор реплик | Предлагаемые горячие клавиши, финальное назначение и доступность переназначения проверять на вертикальном срезе. |
| Плеер | **Esc** — переход к крупному плану плеера и обратно согласно GDD §15 | Не делать конфликтующего действия «пауза на Esc» без решения автора. |
| Игровая структура | Крыша → диалог/скрытые состояния → «Прыжок»/«Уход» → полный хаб → сохранение → новый заход | Соответствует GDD + утверждениям демоверсии. |
| Экран завершения демо | После **двух разных** исходов один экран «Демоверсия завершена», затем возвращение в полный хаб | Не закрывает игру, не блокирует повторные прохождения. Текст/стиль — отдельная проверка автора. |

## Ограничения технической реализации

- Художественный канон: `docs/canon/`; новые решения: `docs/production/DECISIONS_2026-10-19.md`. Не изменять канон автоматически.
- Начать только с **G1: минимальный открываемый Godot-проект** после разрешения автором этапа 1. **Не создавать меню крыши, диалоги, 3D или плеер в G1** — они выполняются отдельными небольшими заданиями.
- Отладочный текст — `PLACEHOLDER_NON_CANON`. Ни музыки, ни графики, ни платных API в первой задаче.
- GitHub Actions после согласованной версии Godot: `godot --headless --path . --editor --quit` для импорта/парсинга. Проверять код возврата и реальные логи. После появления реальной стартовой сцены — отдельная проверка запуска.
- **Сборка Windows `.exe` — отдельная задача**, требует официальных export templates той же версии Godot; CI «зелёный» без Windows smoke test не доказывает запуск на реальном ПК.
- У пользователя основной рабочий инструмент — телефон. Задачи и отчёты Codex доступны через GitHub; отсутствие Cloud Environment не мешает чтению GitHub, но ограничивает непосредственный запуск Godot в Codex. Для тестов можем использовать GitHub Actions, когда получим разрешение на конфигурацию CI.
- **Ограничение бюджета:** одна задача/PR за раз, точные допустимые файлы, остановка после ошибки, никаких автоповторов, запусков иных агентов и установки сторонних инструментов «заодно».
